# Configurar Google Drive — Tamalitos Malitos

> **Configuración y prueba real pendientes.** No se proporcionó un proyecto de Google Cloud ni una cuenta de prueba autorizada. El código no contiene credenciales, secretos ni identificadores OAuth inventados. Las pruebas unitarias no demuestran que una cuenta real haya consentido, subido o recuperado un archivo. Antes de confiar en este respaldo, completar la configuración y la prueba de extremo a extremo descritas aquí.

## 1. Proyecto y autorización

1. En [Google Cloud Console](https://console.cloud.google.com/) crear o seleccionar un proyecto de tu propiedad. Habilitar **Google Drive API** en APIs y servicios → Biblioteca.
2. En Google Auth Platform configurar **Branding** (nombre de app, soporte y contacto; publicar una política de privacidad apropiada para los datos de clientes), **Audience** y **Data Access**. Si el proyecto está en pruebas, añadir la cuenta que usarás como usuario de prueba. Seguir la configuración oficial de autorización Android.[1]
3. Registrar el permiso mínimo `https://www.googleapis.com/auth/drive.appdata`. Es un permiso no sensible para la carpeta privada de datos de la aplicación; no permite ver todo el Drive del usuario.[2]
4. En **Clients → Create client → Android**, registrar exactamente el paquete **`com.tamalitos.malitos`** y el **SHA-1 del certificado que firma el APK instalado**. Android identifica esta aplicación por paquete y firma; no se pega un client ID ni un client secret en Kotlin.[1]
5. Obtener la huella real desde la raíz del proyecto:
   ```bash
   source tools/env.sh
   ./gradlew signingReport --no-daemon --max-workers=1
   ```
   Usar el SHA-1 de `debug` únicamente para APK debug. Para distribución registrar el certificado de release; con Play App Signing usar el SHA-1 del certificado de **firma de aplicación** de Play Console, no solamente el de carga. Cada certificado usado necesita su cliente Android correspondiente.[1]
6. Instalar el APK firmado con ese certificado en un dispositivo Android 8.1+ con Google Play services y una cuenta Google. Un emulador AOSP sin Play services no puede demostrar este flujo.

Esta app usa autorización de Google Identity Services `AuthorizationClient`, no un inicio de sesión de servidor. Solicita el permiso al pulsar una acción de Drive. No usa `requestOfflineAccess`, no necesita backend ni cliente web para esta implementación y no almacena refresh tokens. La documentación general incluye un cliente web para el caso **con backend**; no se utiliza aquí. `authorize()` permite obtener nuevamente un access token después del consentimiento previo; si el usuario debe intervenir, se requiere reconectar desde la pantalla.[1]

## 2. Dónde queda el respaldo

`appDataFolder` es una carpeta privada/oculta: no aparece como archivo normal ni como respaldo del teléfono en la interfaz de Drive. Solamente la aplicación que la creó accede a sus archivos. El usuario puede eliminar estos datos desde la administración de aplicaciones de Drive; no es una garantía de conservación permanente.[2]

No es sincronización entre varios dispositivos. Restaurar reemplaza la base local; no fusiona pedidos ni pagos. Conservar además exportaciones JSON locales independientes del servicio Google.

## 3. Comportamiento implementado y límites

- **Conectar y respaldar:** solicita consentimiento por `AuthorizationClient` y `startIntentSenderForResult`. La Activity debe reenviar `onActivityResult(requestCode, resultCode, data)` a `DriveController.handleActivityResult(...)`; el controlador asigna códigos de autorización desde `9041`, sin reutilizarlos después de restablecer. Un resultado antiguo no consume una autorización nueva pendiente. Se marca conectado **únicamente después** de subir, consultar el ID exacto devuelto, comparar MD5 si Drive lo proporciona, descargar ese mismo ID y comparar todos los bytes, marcarlo verificado y releer sus metadatos.
- El archivo contiene un sobre JSON `format=com.tamalitos.malitos.drive`, `version=1`, `createdAt` en milisegundos y `businessJson`: el JSON versionado que exporta `BusinessStore`. Nombre: `tamalitos-v1-<milisegundos>-<UUID>.json`. Los importes y relaciones permanecen dentro del esquema del almacenamiento local; no se convierte dinero a punto flotante.
- Los marcadores privados `appProperties` identifican formato, versión, SHA-256 de los bytes y verificación. Se retienen el último respaldo verificado y nueve copias reconocidas más recientes por fecha de creación de Drive. La limpieza ocurre **después** de verificar el nuevo archivo y vuelve a revisar cada candidato exacto antes de borrarlo. No se eliminan archivos desconocidos, versiones futuras ni subidas incompletas. Si falla la limpieza se muestra una advertencia; puede haber más de diez archivos, pero no se inventa un fallo de la copia ya verificada.
- El listado recorre páginas (máximo 20 de 100). Si excede el límite, no se usa un listado parcial para borrar o restaurar. El transporte admite sólo HTTPS al host oficial `www.googleapis.com`, sin redirecciones ni certificados permisivos; conexión 20 s, lectura 30 s y desconexión por límite de 90 s por solicitud. Antes/después de cada solicitud se controla un presupuesto total de 4 min; una solicitud ya iniciada puede prolongar ese presupuesto hasta su propio límite de 90 s. Autorización y espera del bloqueo interno: máximo 30 s cada una. HTTP 401/403/429/5xx son fallos reales, no éxitos.
- **Restaurar último:** obtiene el archivo reconocido/verificado más reciente de la cuenta que Google autorice; verifica SHA-256, tamaño y MD5 cuando existe. Muestra un diálogo de reemplazo. **Cancelar no escribe la base.** Al confirmar, exporta primero el estado local a `files/drive-pre-restore/antes-restaurar-<fecha>-<UUID>.json`, hace `fsync` y compara sus bytes; sólo entonces llama a la importación validada y atómica de `BusinessStore`. Instantánea, escritura durable y sustitución mantienen el mismo bloqueo compartido entre instancias, cambios locales y restauraciones locales/Drive; la confirmación queda vinculada a la generación de datos y época de autorización vigentes. Si falta espacio para esa copia, no restaura. Si el JSON de negocio es inválido, la base queda intacta y la copia previa se conserva.
- Las copias de seguridad previas son privadas del dispositivo, no un archivo visible en Descargas. **Respaldo → Exportar copia de seguridad previa** permite seleccionar copias de `drive-pre-restore` y `respaldos-seguridad`, exportar el archivo exacto elegido mediante Android y verificarlo por lectura antes de declarar éxito. Luego puede recuperarse con la importación local, también en release sin `run-as`. **Antes de restaurar, exportar también un JSON fuera de la app.** Desinstalar o borrar datos elimina las copias internas; no se purgan automáticamente y ocupan almacenamiento local.
- El respaldo exporta una instantánea local y cierra SQLite **antes** de usar la red. Pedidos, clientes, pagos y gastos no dependen de Drive ni se bloquean esperando internet. La exportación/importación local sigue siendo independiente de Google.
- **Automático:** desactivado inicialmente. Al habilitarlo y tener una subida verificada, se registra un trabajo único de WorkManager cada **12 horas**, con red conectada; Android puede retrasarlo por batería/Doze. No promete una hora exacta ni respaldo con la app forzada a detenerse. Reiniciar/abrir la app conserva la preferencia y evita trabajos duplicados.
- El worker pide un token en su hilo de trabajo mediante `Tasks.await(..., 30, SECONDS)`, después del consentimiento previo. Nunca abre pantallas en segundo plano. Si Google requiere resolución, falta el permiso o devuelve 401, queda en **Reconecta**, detiene la programación y conserva la intención de automático. Una nueva **subida verificada** vuelve a programarlo. Fallos transitorios de red/429/5xx tienen reintentos limitados; la programación periódica no es un servidor ni una sincronización garantizada.
- **Desconectar** detiene el trabajo, invalida operaciones pendientes y borra preferencias locales de conexión/automático/última copia. No borra los respaldos remotos ni revoca por sí mismo el consentimiento de Google. Para revocar, usar la administración de conexiones de la cuenta Google. La app no solicita nombre/correo ni afirma conocer qué cuenta se eligió: `AuthorizationResult` no garantiza esa identidad.[1] Para cambiar de cuenta, comprobar la cuenta ofrecida por Google y sus permisos; desconectar localmente no equivale a cerrar la sesión Google del teléfono.
- Tokens sólo en memoria de la **aplicación**, nunca en SharedPreferences, WorkManager Data, archivos ni registros; Google Play services administra su propio caché de autorización.[1] Con la dependencia contractual `play-services-auth:21.3.0`, `AuthorizationClient.clearToken` de documentación más reciente no existe; ante 401 se usa `GoogleAuthUtil.clearToken` fuera del hilo UI con espera acotada de 30 s. No se implementa `requestOfflineAccess` ni se almacenan refresh tokens.
- El respaldo es JSON sin cifrado adicional de aplicación: protege la transmisión HTTPS y la privacidad de appDataFolder, pero no es cifrado de extremo a extremo. Maneja datos personales de clientes: proteger el teléfono y la cuenta, y explicar conservación/borrado en la política de privacidad. Tamaño máximo del sobre Drive: **20 MiB**; también aplican los límites más estrictos del importador de negocio.

## 4. Prueba real obligatoria antes de uso

1. Completar Cloud/API/cliente Android, instalar el APK de la firma registrada y usar una cuenta de prueba autorizada. Guardar primero una exportación local en un destino externo elegido por el usuario.
2. Crear datos de prueba identificables sin datos personales reales: cliente, pedido con abonos y gasto. Pulsar **Conectar y respaldar**; elegir la cuenta y aceptar sólo el permiso de datos de app. No dar por completado el respaldo hasta que el estado diga **verificado**.
3. Cambiar un dato local; pulsar **Restaurar último** y **Cancelar**. Comprobar que el cambio sigue existiendo.
4. Volver a restaurar y confirmar reemplazo. Comprobar clientes, pedidos, pagos, deuda, inventario, gastos y relaciones recuperados. Comprobar que existe la copia local previa y practicar la recuperación de un JSON local independiente.
5. Habilitar automático, revisar WorkManager/Background Task Inspector y esperar una ejecución real (Android decide el momento). Desactivar internet: registrar pedidos y pagos debe seguir funcionando. Volver a conectar: verificar una ejecución real y una nueva hora de respaldo **verificado**, no sólo la existencia de un trabajo encolado.
6. Revocar el permiso desde la cuenta Google y probar una ejecución de worker: debe indicar **Reconecta**, sin abrir una Activity en segundo plano. Reconectar y hacer una nueva subida verificada; automático debe recuperarse si seguía habilitado.
7. Probar consentimiento cancelado, proyecto sin API habilitada, firma SHA-1 incorrecta, cuota/errores de red y falta de almacenamiento local. No debe aparecer un falso éxito ni cambiarse la base al fallar una restauración.
8. Generar más de diez copias verificadas y comprobar retención; añadir un archivo no reconocido mediante herramientas propias de prueba y confirmar que nunca se borra. Como appDataFolder no aparece en la UI normal de Drive, esta comprobación requiere instrumentación autorizada de la misma app/proyecto, no inspección de una carpeta normal.[2]
9. Probar rotación/recreación de Activity durante autorización y reenviado de resultados. Si una autorización queda pendiente tras un cierre forzado, **Restablecer autorización de Google Drive** está disponible aunque nunca se haya conectado; limpia la acción pendiente, invalida los resultados anteriores y permite volver a intentar. Después de restaurar se cierran los formularios y se rechazan guardados/confirmaciones de una generación anterior. Probar también la firma de release/Play, no únicamente debug.

## 5. Evidencia automatizada y alcance

Las pruebas `Drive*Test.kt` cubren sobre JSON/versiones/límites, HTTPS permitido, protocolo de subida y comprobación del ID exacto, checksum/media corruptos, HTTP 401/403/429/500, retención sin borrar desconocidos, selección de restauración reconocida, preferencias y copia local, resolución requerida en segundo plano, restricciones de WorkManager y diálogo nativo de cancelación/restauración segura. Las respuestas simuladas están **sólo en los tests** mediante `DriveTransport`; producción utiliza `HttpsURLConnection` hacia Google.

Se realizaron ciclos RED→GREEN reales por comportamiento para serialización, rechazo de versión/formato, subida y lectura exacta, retención, recuperación, HTTPS, metadatos tras marcar verificación, resolución en background y solicitud periódica. Los primeros ciclos usaron Kotlin 2.1.20/JUnit4 con un `org.json` JVM y las mismas pruebas de helper sin las anotaciones Robolectric **únicamente en copias temporales**; después se ejecutaron las pruebas originales con Robolectric SDK 28 y dependencias Android del contrato. Los registros reales están en `$HOME/.hermes/cache/scratch/drive-01-red-jvm.log`, `drive-01-green.log`, `drive-02-{red,green}.log` hasta `drive-09-{red,green}.log`; pruebas adicionales de regresión no se presentan como ciclos RED de funcionalidad nueva. La compilación aislada se hizo con el compilador Kotlin real, Android API 35, auth 21.3.0 y WorkManager 2.9.1, sin modificar Gradle. Un primer intento del build completo no alcanzó las pruebas porque los archivos de otros componentes todavía estaban incompletos; no se cuenta como RED de comportamiento. Tras la indicación de serializar Gradle por RAM limitada se usaron verificaciones aisladas con JVM de 256 MiB. Última ejecución real de las pruebas originales: **JUnit/Robolectric `OK (20 tests)`**, registrada en `$HOME/.hermes/cache/scratch/drive-final-tests.log`; compilación aislada Android también finalizó con código 0.

Para volver a ejecutar dentro del proyecto completo, cuando ningún otro proceso sea dueño del build:
```bash
source tools/env.sh
./gradlew testDebugUnitTest --tests 'com.tamalitos.malitos.Drive*Test' --no-daemon --max-workers=1
```

**No probado todavía:** consentimiento con Google Cloud real, cuenta Google real, HTTPS autorizado de Drive, restauración real desde esa cuenta y ejecución periódica prolongada en un teléfono. La guía y tests no sustituyen esas pruebas. No hay credenciales de ejemplo operativas ni un entorno Drive ficticio en producción.
